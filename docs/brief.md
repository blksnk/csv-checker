# Senior Frontend Engineer - Case Study

## Goal

Build a simplified data import and review flow for non-technical users.

The focus is not completeness, but how you:
- design the user experience
- structure your solution
- handle complexity and ambiguity

## Scenario

You are building a feature that allows users to:
1. Upload a CSV file
2. Review the data
3. Fix errors before importing

The users are non-technical, but the data can be:
- messy
- inconsistent
- partially invalid

## Key Challenge

Users need to understand and fix data issues they do not fully understand.

Your solution should help users:
- identify problems
- understand what needs to be fixed
- take action confidently

## Your Task

Build a simple prototype that demonstrates:
- CSV upload
- data preview
- ability to edit values
- basic validation and feedback

Important: Focus on clarity, usability, and decision-making - not completeness or visual polish.

> If something is unclear, make a reasonable assumption and document it - do not block on missing information.

## Focus Area (Required)

### UX and Interaction for Complex Data

Demonstrate how your solution actively helps users:
- understand what is wrong with their data
- decide what to fix
- feel confident about the result

Examples to consider:
- How do you show validation errors?
- How do users navigate large or complex datasets?
- How do you avoid overwhelming the user?


## Deliverables

### 1. Code Repository

- A working prototype (can be simple)
- Focus on structure and clarity, not production polish

### 2. Short Design Document (max ~1–2 pages)

Include:

#### Architecture Overview

- How you structured your solution
- Key design decisions

#### Architecture Decision Record (ADR)

- One important decision you made
- Alternatives you considered
- Why you chose this approach

#### UX Decisions

How you approached:
- complexity
- validation
- user guidance

#### Trade-offs

- What you simplified
- What you would improve with more time

### 3. Video (max 5 minutes)
- Highlight only the most important ideas
- Focus on key decisions and structure
- Details can be discussed in the interview

## Time Expectation
We expect this to take approximately 2–4 hours.

Please focus on what matters most and avoid overengineering.

> We strongly prefer a simple, well-reasoned solution over a complex or overengineered one.
